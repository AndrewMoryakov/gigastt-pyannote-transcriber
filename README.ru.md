```powershell
.\scripts\run.ps1 -InputAudio '.\media\запись.m4a'   # -> transcript.{md,txt,srt,vtt,json}
```

**Fourvoices: GigaSTT + pyannote для четырёх голосов.** Локальный CPU-конвейер для русскоязычных записей: **GigaSTT 2.21.0 / GigaAM v3 RNNT** распознаёт слова и их время, **pyannote Community-1** определяет, кто и когда говорил, а Python-пакет `fourvoices` совмещает результаты по времени. (Пакет и CLI называются `fourvoices`, репозиторий — `gigastt-pyannote-transcriber`.) Исходное аудио, модели, токены и результаты намеренно исключены из Git.

Вокруг этого ядра в репозитории есть восемь PowerShell-скриптов (установка, скачивание и проверка моделей, doctor, запуск, повторный рендер, оценка качества, тесты, проверка гигиены репозитория), CLI из пяти команд (`run`, `render`, `diarize-preload`, `doctor`, `evaluate`), конфигурационный файл с проверкой схемы, возобновляемые каталоги заданий с манифестом, шаг повторного рендера по карте говорящих без повторного вывода моделей и набор тестов pytest с CI-процессом для Windows.

*Основная версия документации — английская: [README.md](README.md). Этот файл поддерживается как перевод; при расхождении верным считается английский.*

Версия 0.1.0, только Windows. Нужны учётная запись Hugging Face и read-токен (`HF_TOKEN` требуется при каждой транскрибации), а зафиксированы исполняемый файл GigaSTT и ревизия pyannote (веса, которые он загружает, GigaSTT проверяет сам) — см. [Статус и известные ограничения](#статус-и-известные-ограничения).

## Простыми словами

### Проблема

У вас есть запись разговора нескольких людей на русском — интервью, встреча, телефонный звонок — и нужно знать не только *что* было сказано, но и *кто* это сказал, со временем и в виде, который можно цитировать. Обычное распознавание речи выдаёт один блок текста без говорящих. Разделение по говорящим — вторая, отдельная задача, и два результата нужно совместить по времени. В облаке это значит загружать запись; локально — ставить несколько моделей и инструментов, которые должны работать вместе, а повторный запуск после небольшого изменения не должен стоить часов.

### Для кого

Для тех, кто работает с русскоязычным аудио с несколькими говорящими на Windows-компьютере и хочет проверяемый результат: журналисты и исследователи, расшифровывающие интервью, те, кто документирует встречи или звонки. Значения по умолчанию рассчитаны на разговор четырёх человек, записанный одним микрофоном. Опытные пользователи получают полный CLI, настройку по каждому ключу, описанный алгоритм слияния и структурированный JSON для собственных инструментов.

### Что вы получаете

- **Транскрипт «кто что сказал»** из одного аудиофайла: у каждой реплики есть метка говорящего и интервал времени; форматы — Markdown, простой текст, SRT, VTT и JSON.
- **Честная неопределённость.** Перекрытия речи и сомнительная привязка к говорящему помечаются в тексте, а не скрываются, — видно, где стоит переслушать.
- **Локальная обработка.** Распознавание и диаризация выполняются на вашем процессоре, без GPU. Сеть нужна для установки и скачивания моделей; сама транскрибация идёт по локальным файлам моделей.
- **Ничего не смешивается молча.** Манифест фиксирует, какие этапы готовы; повторный запуск использует готовые этапы, а изменение опции, влияющей на результат, останавливает запуск, пока вы не подтвердите это флагом `--force`.
- **Имена — только по вашему решению.** Метки вроде `SPEAKER_00` становятся именами в файлах Markdown, text, SRT и VTT лишь через карту говорящих, которую вы заполняете после прослушивания; `transcript.json` всегда сохраняет исходные метки `SPEAKER_nn`, а конвейер имена не угадывает.
- **Защищённый репозиторий.** Аудио, токены и модели исключены из Git и проверяются скриптом гигиены; скачанный архив GigaSTT проверяется по SHA-256 до распаковки и запуска.

### Чем он не является

- Не облачный сервис и не GPU-конвейер: зафиксированная сборка PyTorch — только CPU.
- Не для других языков и платформ: модель распознавания русская, скрипты — PowerShell для Windows 10/11 x64, а CI работает только на Windows.
- Не гарантия дословной точности: цитаты всегда проверяйте на слух по исходной записи.
- Не автоматическое именование говорящих: метки сами в имена не превращаются.
- Не разделитель стереоканалов: многоканальный вход останавливает запуск, если вы явно не разрешили сведение в моно.
- Не полностью закреплён хешами: веса pyannote закреплены только ревизией; веса GigaAM проверяет `gigastt` по вшитым в него SHA-256, а не этот репозиторий.
- Не офлайн с первой минуты: для установки и скачивания моделей нужны сеть и около 10 ГБ, а также учётная запись Hugging Face для gated-модели pyannote.

### Глоссарий

| Термин | Что означает здесь |
|---|---|
| **ASR / GigaSTT** | Автоматическое распознавание речи. GigaSTT — консольная программа (зафиксированный релиз), которая запускает модель GigaAM v3 RNNT и возвращает слова с временем начала и конца. |
| **Диаризация / pyannote Community-1** | Определение того, *кто и когда говорил*. Community-1 — используемая модель pyannote, которую скачивают с Hugging Face по зафиксированной ревизии. |
| **Exclusive-диаризация** | Результат pyannote, в котором в любой момент активен не более одного говорящего; слова назначаются по нему. Обычный результат (допускающий перекрытия) нужен, чтобы находить одновременную речь. |
| **Метка говорящего** | Имя кластера вроде `SPEAKER_00` либо `UNKNOWN` для слова, которое не удалось ни к какому сегменту отнести. |
| **Реплика (turn)** | Серия подряд идущих слов одного говорящего; разбивается, когда пауза между словами превышает `max_turn_gap`. |
| **Каталог задания** | Папка для одной записи, названная по имени файла и первым 12 символам SHA-256 аудио. |
| **Манифест** | `manifest.json` в каталоге задания: отпечаток входа, использованные опции и список готовых этапов. |
| **Карта говорящих** | Небольшой YAML-файл, сопоставляющий `SPEAKER_00` и т. д. именам, которые вы выбираете после прослушивания. Применяется к файлам Markdown, text, SRT и VTT, но не к JSON. |
| **Gated-модель / `HF_TOKEN`** | Модель pyannote требует принять её условия на Hugging Face; read-токен подтверждает это и нужен при каждой транскрибации. |
| **ITN** | Обратная нормализация текста: числа, произнесённые словами, записываются цифрами («двадцать три» → «23»). |

## Что внутри

Всё перечисленное здесь реализовано в этом репозитории; в коде и документации ничего не помечено как экспериментальное или запланированное. Последний подраздел перечисляет то, чего нет.

### Конвейер транскрибации

- **Подготовка аудио.** Одна запись превращается в два WAV-файла 16 кГц моно: почти исходный — для диаризации и мягко отфильтрованный — для распознавания. Исходный файл не меняется; многоканальный вход отвергается, пока вы не разрешите сведение в моно. → [Как обрабатывается звук](#как-обрабатывается-звук)
- **Распознавание.** Зафиксированный исполняемый файл GigaSTT выдаёт слова с временем начала и конца, при необходимости — пунктуацию, нормализацию чисел и определение речевой активности. → [Почему параметры именно такие](#почему-параметры-именно-такие)
- **Диаризация.** pyannote Community-1 по зафиксированной ревизии с заданным числом говорящих (по умолчанию 4). Несовпадение числа сохраняется и сопровождается предупреждением либо отвергается при `-StrictSpeakers`. → [Почему параметры именно такие](#почему-параметры-именно-такие)
- **Слияние.** Каждое слово получает говорящего с наибольшим перекрытием; в промежутках используется ближайший сегмент либо `UNKNOWN`; перекрытие и неопределённость записываются; слова группируются в реплики. → [Как слово получает говорящего](#как-слово-получает-говорящего)
- **Рендер.** Markdown, TXT, SRT, VTT и JSON за один запуск; субтитры режутся по границам слов с настоящими таймингами. → [Выходные файлы подробно](#выходные-файлы-подробно)

### Надёжность и воспроизводимость

- **Возобновляемые задания.** Готовые этапы читаются с диска, только если их подтверждает манифест; прерванный запуск продолжается с последнего завершённого этапа. → [Что лежит в каталоге задания](#что-лежит-в-каталоге-задания)
- **Отказ вместо смешивания.** Изменение опции, влияющей на результат, или другой вход в том же каталоге задания останавливают запуск, пока не указан `--force`. → [Что лежит в каталоге задания](#что-лежит-в-каталоге-задания)
- **Фиксации.** Исполняемый файл GigaSTT — по URL и SHA-256; pyannote — по полной git-ревизии; CLI отвергает конфигурацию, запрашивающую другую модель или ревизию. → [Безопасность и воспроизводимость](#безопасность-и-воспроизводимость)
- **Строгая конфигурация.** Неизвестные секции и ключи отвергаются, поэтому опечатка не может выглядеть как настройка. → [Справочник по конфигурации](#справочник-по-конфигурации)

### Работа с результатом

- **Имена, назначенные вручную.** Заполните карту говорящих после прослушивания и перерендерите без повторного вывода моделей; имена попадают в Markdown, text, SRT и VTT, а JSON сохраняет метки. → [Назначение говорящих вручную](#назначение-говорящих-вручную)
- **Пометки.** `[перекрытие речи]` для одновременной речи и `[спикер под вопросом]` для сомнительной привязки. → [Что помечается в транскрипте](#что-помечается-в-транскрипте)
- **Структурированный JSON.** Слитый JSON содержит каждое слово с говорящим, основанием привязки и флагами, а также реплики. → [Выходные файлы подробно](#выходные-файлы-подробно)

### Инструменты вокруг конвейера

- **Восемь PowerShell-скриптов.** `install`, `download-models`, `doctor`, `run`, `rerender`, `evaluate`, `test` и `check-repo-hygiene`. → [Справочник команд](#справочник-команд)
- **CLI из пяти команд.** `run`, `render`, `diarize-preload`, `doctor` и `evaluate`, с опциями, которые скрипты не открывают (например, `--force`). → [Справочник команд](#справочник-команд)
- **Гигиена репозитория и тесты.** Скрипт, который падает, если в Git попали аудио, модели, токены или секреты, набор pytest, ruff и CI-процесс для Windows. → [Статус и известные ограничения](#статус-и-известные-ограничения)

### Не реализовано

Другие языки, GPU/CUDA, скрипты для Linux или macOS, параллельная обработка нескольких файлов, потоковое/реальное время, автоматическое именование говорящих и диаризация с учётом стереоканалов в этот репозиторий не входят. См. [Чем он не является](#чем-он-не-является) и [Статус и известные ограничения](#статус-и-известные-ограничения).

## Как это работает

<p align="center">
  <img src="docs/assets/gigastt-pyannote-transcriber-how-it-works.png" alt="gigastt-pyannote-transcriber: один аудиофайл проходит через GigaSTT (что сказано и когда) и pyannote (кто и когда говорил), результаты сливаются по времени, и каждое слово получает говорящего; на выходе — транскрипт в JSON, Markdown, TXT, SRT и VTT" width="100%">
</p>

1. **Подготовка двух копий звука.** Из одной записи получаются почти исходная моно-копия 16 кГц для диаризации и мягко отфильтрованная копия для распознавания.
2. **Распознавание слов.** GigaSTT (RNNT) выдаёт слова с временем начала и конца.
3. **Поиск говорящих.** pyannote Community-1 получает `num_speakers=4` и строит exclusive-диаризацию.
4. **Совмещение по времени.** `fourvoices` назначает каждому слову говорящего, помечает перекрытия и сомнительную привязку и записывает транскрипт в пяти форматах.
5. **Имена — вручную.** Послушайте длинные реплики каждого кластера, заполните карту говорящих и перерендерите — метки автоматически в имена не превращаются. Имена попадают в файлы Markdown, text, SRT и VTT; JSON сохраняет метки.

CLI печатает пять этапов по ходу работы, и каждый этап оставляет файл и запись в манифесте:

| Этап | Выводится как | Пишет | Ключ манифеста |
|---|---|---|---|
| 1 | `[1/5] Preparing separate ASR and diarization audio…` | `audio/asr.wav`, `audio/diarization.wav` | `audio` |
| 2 | `[2/5] Running GigaSTT RNNT…` (или `Reusing GigaSTT timestamps.`) | `intermediate/gigastt.json` | `asr` |
| 3 | `[3/5] Running pinned Community-1 (N speakers)…` (или `Reusing pyannote diarization.`) | `intermediate/pyannote.json` | `diarization` |
| 4 | `[4/5] Assigning words by exclusive maximum overlap…` (или `Reusing merged transcript.`) | `intermediate/merged.json` | `merge` |
| 5 | `[5/5] Rendering …` | `transcript.{md,txt,srt,vtt,json}` | `render` |

## Быстрый старт

Краткая версия; каждый шаг разобран в [порядке запуска](#порядок-запуска-коротко) и в [подробной настройке Windows](#быстрый-старт-на-чистой-windows) ниже. Сначала примите условия gated-модели pyannote на Hugging Face и создайте read-токен (см. [Однократный доступ](#однократный-доступ-к-gated-модели-hugging-face)).

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install.ps1 -InstallFfmpeg

# Токен живёт только в текущем PowerShell и не записывается на диск:
$secureToken = Read-Host 'HF read token' -AsSecureString
$env:HF_TOKEN = [Net.NetworkCredential]::new('', $secureToken).Password

.\scripts\download-models.ps1       # нужна сеть, ~10 ГБ
.\scripts\doctor.ps1                # все строки должны быть [OK]

# положите записи в .\media\, затем:
.\scripts\run.ps1 -InputAudio '.\media\запись.m4a'
```

Результаты появятся в `..\gigastt-pyannote-output\<задание>\` — в соседнем с репозиторием каталоге, откуда они не могут случайно попасть в commit.

## Порядок запуска, коротко

Полная последовательность от чистой машины до готового транскрипта. Каждый шаг
подробно разобран ниже.

| # | Шаг | Когда |
|---|-----|-------|
| 1 | Принять условия модели на Hugging Face и создать read-токен | один раз |
| 2 | `.\scripts\install.ps1 -InstallFfmpeg` | один раз |
| 3 | Задать `$env:HF_TOKEN` | в каждом новом окне PowerShell |
| 4 | `.\scripts\download-models.ps1` | один раз, нужна сеть, ~10 ГБ |
| 5 | `.\scripts\doctor.ps1` — все строки должны быть `[OK]` | после установки |
| 6 | `.\scripts\test.ps1` — линтер, тесты, гигиена репозитория | по желанию |
| 7 | Положить записи в `.\media\` | перед работой |
| 8 | `.\scripts\run.ps1 -InputAudio '.\media\запись.m4a'` | каждая запись |
| 9 | Прослушать кластеры, заполнить speaker-map, `.\scripts\rerender.ps1` | после прогона |

**`HF_TOKEN` нужен не только для скачивания, но и при каждой транскрибации:**
диаризация отказывается стартовать без него, даже когда все веса уже лежат на
диске. Если удалить токен из окружения после установки, шаг 8 остановится с
`error: Set HF_TOKEN...`. Либо задавайте токен в каждом новом окне PowerShell,
либо один раз положите его в локальный `.env` (файл игнорируется Git).

## Быстрый старт на чистой Windows

Перенесите репозиторий на машину (`git clone`, если он где-то опубликован,
иначе просто скопируйте каталог). Каталоги `.venv`, `models`, `tools\bin` и
`tools\downloads` копировать не нужно и не следует: в `.venv` записаны
абсолютные пути исходной машины, остальное восстановят скрипты установки.

```powershell
Set-Location .\gigastt-pyannote-transcriber
Set-ExecutionPolicy -Scope Process Bypass

# uv, Python 3.11, .venv и CPU-зависимости; при необходимости также ffmpeg:
.\scripts\install.ps1 -InstallFfmpeg

# Токен живёт только в текущем PowerShell и не записывается на диск:
$secureToken = Read-Host 'HF read token' -AsSecureString
$env:HF_TOKEN = [Net.NetworkCredential]::new('', $secureToken).Password
```

Если ffmpeg был установлен через winget и ещё не виден в `PATH`, откройте
новое окно PowerShell, вернитесь в каталог репозитория и снова задайте токен
командами выше. Затем выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\download-models.ps1
.\scripts\doctor.ps1
.\scripts\test.ps1
```

Токен на этом шаге **не удаляйте**: он понадобится и при самой транскрибации.
Удалять его имеет смысл только когда работа на сегодня закончена
(`Remove-Item Env:HF_TOKEN`), помня, что в следующем окне PowerShell его
придётся задать снова.

`download-models.ps1` скачивает строго GigaSTT **v2.21.0** для Windows x64,
проверяет архив по SHA-256 из `tools/tools.lock.json`, затем получает RNNT INT8,
VAD, пунктуацию и точную ревизию pyannote. Непроверенный `gigastt.exe` не
запускается.

Положите записи в игнорируемый каталог `media`:

```powershell
Copy-Item 'D:\Аудио\беседа-1.m4a' .\media\
Copy-Item 'D:\Аудио\беседа-2.m4a' .\media\

.\scripts\run.ps1 -InputAudio @(
    '.\media\беседа-1.m4a',
    '.\media\беседа-2.m4a'
)
```

Если говорящих не четверо, укажите их число: `-NumSpeakers 3`.

Файлы обрабатываются **строго последовательно**, чтобы два тяжёлых CPU-задания
не конкурировали за память. Результаты по умолчанию появятся в соседнем с
репозиторием каталоге `gigastt-pyannote-output\`, то есть не смогут случайно
попасть в commit. Скрипт запрашивает четыре кластера говорящих, но имена людей
автоматически не угадывает.

Если pyannote нашёл другое число говорящих (например, один участник почти всё
время молчал), результат диаризации всё равно сохраняется, а в вывод попадает
предупреждение: терять десятки минут работы из-за такого расхождения нельзя.
Чтобы вместо предупреждения получать отказ, добавьте `-StrictSpeakers` —
результат при этом тоже останется на диске.

Если запись стереофоническая, программа сначала остановится, не смешивая
каналы молча. Прослушайте левый и правый каналы отдельно. Если полезного
пространственного разделения нет, повторите команду с `-AllowDownmix`.

## Что лежит в каталоге задания

Имя задания — это очищенное имя файла плюс первые 12 символов SHA-256
исходного аудио, поэтому две разные записи никогда не попадут в один каталог.

```
<имя>-<хэш>/
  manifest.json          что и когда посчитано, с какими параметрами
  audio/asr.wav          копия для распознавания (с фильтром)
  audio/diarization.wav  копия для диаризации (без фильтра)
  intermediate/gigastt.json    слова и их время
  intermediate/gigastt.log     журнал GigaSTT за этот прогон
  intermediate/pyannote.json   сегменты говорящих
  intermediate/merged.json     совмещённый результат
  transcript.{md,txt,srt,vtt,json}
```

Распознавание и диаризация занимают на CPU минуты на час записи, поэтому
обе стадии примерно раз в полминуты сообщают о ходе работы: распознавание
считает обработанные окна (с VAD их число заранее неизвестно, поэтому это не
проценты) и в конце пишет скорость, диаризация называет текущий шаг pyannote и
его долю. Это обычные строки, они читаются и в перенаправленном журнале.

Повторный запуск той же команды не пересчитывает готовые этапы: они берутся из
`intermediate/`, но только если записаны в `manifest.json`. Поэтому потерянный
или повреждённый манифест приводит к честному пересчёту, а не к транскрипту,
склеенному из результатов с разными настройками.

Если изменить параметр, влияющий на результат (число говорящих, фильтры,
пороги слияния, вариант модели), запуск остановится с требованием `--force`:
молча смешивать старые и новые этапы нельзя. Число потоков PyTorch на результат
не влияет и пересчёта не требует. Прерванный запуск (Ctrl+C) продолжается с
последнего **завершённого** этапа: этап, прерванный на середине, считается
непосчитанным и выполняется заново целиком.

Этапы распознавания и диаризации также запоминают, какими программами они
посчитаны. Новый релиз GigaSTT меняет сами слова и их время, поэтому если
запускаемый GigaSTT (`run.ps1` всегда запускает закреплённый в
`tools/tools.lock.json`) отличается от записанного в задании (или версия не записана — так у заданий,
сделанных до появления этой проверки), заново выполняется только
распознавание и всё, что на нём построено; диаризация сохраняется. Другая
версия `pyannote.audio` или `torch` лишь выводит предупреждение: модель
закреплена ревизией, а диаризация — самый дорогой этап; для пересчёта
используйте `--force`. Если распознавание или диаризация пересчитаны,
совмещённый результат строится заново, а не берётся из прошлого запуска.

Некоторые проблемы GigaSTT сообщает только в своём журнале, завершаясь при
этом успешно, поэтому его предупреждения дублируются на экран, а сам журнал
сохраняется в `intermediate/`. Одна такая проблема проверяется явно: если
пунктуация запрошена, а длинный текст пришёл без единого знака препинания,
запуск предупреждает об этом, а манифест помечает
`punctuation_missing: true`.

Менять оформление можно без всякого инференса — командой `render`: она
перечитывает `merged.json`. Лимиты субтитров и пометки неуверенности она
берёт те, с которыми задание отрисовывалось в последний раз, если не передан
флаг (у заданий, отрисованных до появления этой записи, — значения по
умолчанию). Команда откажется работать, если манифест больше не ручается за
`merged.json`: так бывает, когда прерван запуск, пересчитавший распознавание
или диаризацию, до пересборки результата; сначала завершите этот запуск.

## Назначение говорящих вручную

После первого прохода прослушайте несколько длинных реплик каждого кластера.
Скопируйте карту и замените подписи:

```powershell
Copy-Item .\config\speaker-map.example.yaml `
    ..\gigastt-pyannote-output\<имя-задания>\speaker-map.yaml
notepad ..\gigastt-pyannote-output\<имя-задания>\speaker-map.yaml

.\scripts\rerender.ps1 `
    -JobDir ..\gigastt-pyannote-output\<имя-задания> `
    -SpeakerMap ..\gigastt-pyannote-output\<имя-задания>\speaker-map.yaml
```

Не назначайте имя по короткому «да/угу»: для проверки используйте длинные,
хорошо слышимые фрагменты. Подпись, которой нет в транскрипте, никого не
переименует, и запуск сообщает об этом, а не делает вид, что замена сработала.
Перебивания и одновременная речь требуют ручной
вычитки независимо от модели.

Карта применяется только при рендере файлов Markdown, text, SRT и VTT.
`transcript.json` — это слитые данные, записанные без изменений, поэтому после
перерендера в его `speakers`, `turns` и `words` по-прежнему стоят `SPEAKER_00` и
т. д.; инструмент, читающий JSON, должен сам применить то же сопоставление
меток и имён. Применённые имена записываются на этапе `render` в `manifest.json`
(`speaker_names`).

## Оценка качества на своих записях

Автоматическую расшифровку нужно с чем-то сверять. `evaluate` сравнивает
готовое задание с эталоном, которому вы доверяете, и выдаёт два числа:

- **WER** — доля слов эталона, которые заменены, пропущены или вставлены
  лишними, после приведения к нижнему регистру, замены `ё` на `е` и удаления
  знаков препинания;
- **точность атрибуции** — среди слов, которые есть в обоих текстах, доля
  отданных правильному человеку. Кластеры сопоставляются с именами эталона
  один к одному так, чтобы совпадение было наибольшим; `UNKNOWN` не
  сопоставляется никогда и всегда считается ошибкой.

Эталон — текстовый файл в формате `transcript.txt`: одна реплика на строку,
`[чч:мм:сс–чч:мм:сс] Имя: текст`. Время необязательно, пометки вроде
`[перекрытие речи]` игнорируются, строка без `Имя:` продолжает предыдущего
говорящего, строки с `#` — комментарии. Два часа вручную никто не
расшифровывает, поэтому эталон обычно покрывает фрагмент: оцениваются только
слова внутри его промежутка времени (или задайте `-Start`/`-End`).

```powershell
# Эталон: скопируйте транскрипт, оставьте фрагмент на несколько минут,
# прослушайте и исправьте в нём каждое слово и каждое имя.
Copy-Item ..\gigastt-pyannote-output\<задание>\transcript.txt .\media\reference.txt
notepad .\media\reference.txt

.\scripts\evaluate.ps1 ..\gigastt-pyannote-output\<задание> -Reference .\media\reference.txt
```

Результат пишется в `<задание>\evaluation.json` вместе со всеми местами, где
слова расходятся, и их временем в записи — понятно, что переслушать. Само
задание не изменяется.

Две оговорки:

- **Эталон, полученный правкой транскрипта, оптимистичен.** Ошибки, которые
  читаются естественно, легко пропустить, когда текст перед глазами. Для
  честной оценки наберите фрагмент с нуля, слушая запись.
- **Пишите числа так же, как транскрипт.** Нормализация превращает «двадцать
  три» в «23»; эталон, где число написано словами, засчитает это как ошибку.

Когда эталон есть, любое изменение — новый GigaSTT, другие фильтры, другое
число говорящих — можно оценивать цифрами, а не на слух.

## Как обрабатывается звук

- Для pyannote создаётся почти исходная версия: mono, 16 кГц, без агрессивного
  шумоподавления (`audio.diarization_filter`).
- Для ASR создаётся отдельная версия с мягким high-pass 80 Гц и loudnorm
  (`audio.asr_filter`).
- Стерео сначала следует прослушать по каналам: иногда левый/правый канал уже
  разделяет собеседников. Автоматическое downmix до такой проверки нежелательно.
- Оригинал не изменяется.

Базовые настройки находятся в `config/default.yaml`. Каждый ключ там реально
читается конвейером, а неизвестные ключи отвергаются с ошибкой — опечатка не
может молча выглядеть настройкой. Относительные пути в конфиге отсчитываются от
корня проекта (ближайший каталог с `pyproject.toml`), а не от текущего каталога.

## Почему параметры именно такие

Значения по умолчанию выбраны под одну задачу: разговор четырёх человек на
русском, записанный одним микрофоном, который потом придётся цитировать и
сверять на слух. Ниже — что стоит за каждым и что произойдёт, если сдвинуть.

### Два разных файла из одного исходника

`audio.diarization_filter: null` и
`audio.asr_filter: highpass=f=80,loudnorm=I=-18:LRA=11:TP=-2`.

Это ключевое решение всего конвейера. Распознаванию важна разборчивость,
диаризации — тембр. Нормализация громкости и шумоподавление меняют именно те
характеристики голоса, по которым кластеризуются говорящие, поэтому диаризация
получает звук максимально близкий к исходному: только моно и 16 кГц.

Копия для ASR чистится мягко. 80 Гц лежит ниже основного тона обычного
говорящего голоса, поэтому high-pass убирает гул, тряску стола и ветер, почти
не задевая речь. `loudnorm` приводит запись к предсказуемой громкости
(−18 LUFS), чтобы тихая и громкая записи распознавались одинаково. Сильнее
обрабатывать рискованно: чем агрессивнее фильтр, тем выше шанс потерять тихие
окончания слов и короткие реплики.

### Диаризация

`num_speakers: 4` — число говорящих задаётся, а не угадывается: при
фиксированном числе кластеризация воспроизводима от запуска к запуску. Если
pyannote нашёл другое количество, результат всё равно сохраняется и выводится
предупреждение.

`model` + `revision` — модель закреплена не только по имени, но и по ревизии.
Обновление на стороне Hugging Face не должно менять то, что сказал бы уже
выданный транскрипт. Конфигурация с другими значениями отвергается, а не
используется молча.

`device: cpu` — зафиксирована CPU-сборка PyTorch, CUDA в проекте нет.

**Почему Community-1, а не Precision.** Коммерческие модели pyannote
(`precision-2`, а с сентября 2026 года `precision-3` за тем же конвейером
`pyannote/speaker-diarization-precision`) заметно точнее: по собственным
замерам pyannote на записях совещаний вроде AMI и AliMeeting ошибка
диаризации около 15 % против 20 %. Но доступны они только через облачный API
pyannoteAI: конвейер из `pyannote.audio` загружает аудиофайл на серверы
pyannoteAI и требует платного ключа, весов для скачивания нет (самостоятельное
размещение предлагается только по корпоративным контрактам). Проект
существует ради того, чтобы записи не покидали машину, поэтому остаётся на
Community-1 — самой новой открытой модели — и не предлагает облачную модель
даже как опцию. По той же причине безусловно выключена телеметрия pyannote
(она отправляет длительность файла и число говорящих на `otel.pyannote.ai`).

### Распознавание

`model_variant: rnnt` — весь конвейер построен на пословных таймингах: без
массива `words` с началом и концом каждого слова слияние с диаризацией
невозможно, и распознавание завершится ошибкой. Менять вариант можно только на
такой, который тоже отдаёт word timestamps.

`punctuation: true`, `itn: true` — GigaSTT применяет пунктуацию и нормализацию
чисел только к сплошному тексту, оставляя `words[]` сырыми. Слияние переносит
обработанное написание обратно на слова с таймингами и только там, где
нормализованные формы совпадают точно: замена «двадцать три» → «23» откатывается
к сырому слову, а не выдумывает соответствие. Отключение стоит читаемости, но не
таймингов.

`vad: true` — детектор речи не пускает распознаватель в длинные паузы, где он
иначе волен придумать текст.

**Почему GigaSTT 2.21.0.** У ранее закреплённой версии 2.15.0 было два
дефекта, бьющих ровно по тем записям, для которых сделан конвейер; оба
исправлены в 2.16.0 и оба воспроизведены здесь на настоящей русской речи.
Когда текст перерастал окно модели пунктуации в 2048 токенов (запись на
28 минут, 1 574 слова), пунктуация молча пропадала: код возврата 0, текст в
нижнем регистре без единого знака. А с `--vad` всё длиннее 30 минут
отвергалось целиком. 2.21.0 декодирует файлы ограниченными окнами без
потолка по длительности (проверено сквозным прогоном 36-минутной записи),
расставляет пунктуацию в длинных текстах перекрывающимися окнами и при каждой
загрузке сверяет веса распознавателя с закреплёнными SHA-256. Все флаги,
которые передаёт проект, работают как прежде, а на одном и том же аудио сырые
слова различаются в единицах на тысячу. Задания, сделанные на 2.15.0, при
следующем запуске будут распознаны заново автоматически (см.
[Что лежит в каталоге задания](#что-лежит-в-каталоге-задания)).

### Слияние

`max_turn_gap: 1.5` — пауза внутри речи одного человека, после которой реплика
делится надвое. Значение выбрано с запасом относительно обычных пауз между
фразами, чтобы реплика не рвалась на вдохе. Уменьшите, если нужны более дробные
реплики; увеличьте, если собеседник говорит с длинными раздумьями.

`nearest_max_gap: 0.5` — насколько далеко слово может отстоять от ближайшего
exclusive-сегмента, прежде чем его говорящий станет `UNKNOWN`. Больше значение —
меньше `UNKNOWN`, но больше догадок; меньше — больше честно неатрибутированных
слов. Такие слова попадают в пометку «спикер под вопросом».

### Вывод

`mark_uncertain_words: true` — реплика помечается, если минимум половина её слов
привязана к говорящему без подтверждённого перекрытия. Один осторожный переход в
длинной фразе — норма, половина — повод переслушать.

`subtitle_max_seconds: 6`, `subtitle_max_chars: 84` — примерно две строки по
42 символа на несколько секунд экрана. Реплика в разговоре длится минуты, и без
нарезки субтитры нечитаемы.

### Потоки

`-TorchThreads` по умолчанию равен числу логических процессоров машины
(`os.cpu_count()`), поэтому репозиторий ведёт себя разумно на любом железе без
правки. Важно: считаются именно **логические** процессоры — на Ryzen 9 7950X
это 32, а не 16 физических ядер. Декодирование упирается в пропускную
способность памяти, и SMT здесь часто не помогает, а мешает, так что если
нужно число физических ядер — задайте его явно: `-TorchThreads 16`.

`-TorchInteropThreads` по умолчанию 1: ограничивает межоперационный
параллелизм, чтобы потоки не конкурировали за одни ядра. Учтите: PyTorch
принимает эту настройку только до первой параллельной операции, поэтому она
применяется по возможности и может тихо не сработать — на корректность
результата это не влияет.

В конфиге этих ключей нет намеренно: на результат они не влияют, живут только
в командной строке и пересчёта задания не требуют. В `run.ps1` значение `0`
означает «пусть fourvoices решает сам».

## Что помечается в транскрипте

Сами транскрипты русские, поэтому пометки внутри них (`перекрытие речи`, `спикер под вопросом`) тоже русские; этот документ описывает работу с конвейером, а не язык вывода.

- `[перекрытие речи]` — по regular-диаризации в этом интервале говорят двое.
- `[спикер под вопросом]` — минимум половина слов реплики привязана к
  говорящему без подтверждённого exclusive-перекрытия (ближайший сегмент,
  ничья между двумя спикерами или полное отсутствие сегмента).

Отключается ключом `output.mark_uncertain_words` или флагом
`--no-mark-uncertain` у команды `render`, а включается обратно флагом
`--mark-uncertain`. Обе пометки — повод переслушать
фрагмент, а не признак ошибки.

## Субтитры

Реплика в разговоре может длиться минуты, поэтому в SRT и VTT она режется на
отдельные cue по границам слов: тайминги остаются настоящими, а не
рассчитанными пропорционально. По умолчанию не длиннее 6 секунд и 84 символов
(две строки по 42), имя говорящего повторяется в каждом cue.

Пределы задаются ключами `output.subtitle_max_seconds` и
`output.subtitle_max_chars` либо флагами `--subtitle-max-seconds` /
`--subtitle-max-chars` у команды `render`; `0` отключает соответствующий
предел. Если в `merged.json` нет пословных таймингов, реплика остаётся одним
cue — неверная временная метка хуже длинного субтитра.

## Как слово получает говорящего

Это шаг слияния (`src/fourvoices/merge.py`). Он работает со словами, которые вернул GigaSTT, и с двумя разметками pyannote, сохранёнными в `intermediate/pyannote.json`: *exclusive*-сегментами (один говорящий в каждый момент) и *regular*-сегментами (перекрытия допускаются).

1. **Побеждает наибольшее перекрытие.** Для каждого слова суммируется время, которое оно делит с exclusive-сегментами каждого говорящего; побеждает тот, у кого суммарно больше. Слово нулевой длины рассматривается как крошечный интервал. Равные суммы помечают слово как `ambiguous`.
2. **В промежутках используется ближайший сегмент.** Если слово не покрыто ни одним exclusive-сегментом, берётся ближайший, если он лежит не дальше `nearest_max_gap` секунд (по умолчанию 0,5); слово записывается как назначенное по `nearest`. Если дальше — говорящий слова `UNKNOWN`.
3. **Перекрытие берётся из regular-разметки.** Слово или реплика помечается как перекрывающаяся, когда одновременно активны regular-сегменты *разных* говорящих; сегменты, которые лишь соприкасаются, не считаются.
4. **Слова становятся репликами.** Подряд идущие слова одного говорящего образуют одну реплику; новая реплика начинается, когда меняется говорящий или пауза между словами превышает `max_turn_gap` (по умолчанию 1,5 с).
5. **Сомнительные реплики помечаются.** Реплика считается `uncertain`, когда как минимум половина её слов опирается на что-то более слабое, чем подтверждённое перекрытие (`nearest`, `UNKNOWN` или ничья). Именно это даёт пометку `спикер под вопросом`.
6. **Отображаемый текст сохраняет пунктуацию GigaSTT там, где это безопасно.** GigaSTT применяет пунктуацию и нормализацию чисел только к тексту верхнего уровня, а слова оставляет сырыми. Слияние переносит обработанное написание обратно на слова с метками времени только там, где нормализованные формы совпадают точно (регистр, пунктуация по краям и различие `ё`/`е` игнорируются); иначе остаётся сырое слово. Доля совпавших слов сохраняется как `punctuation_alignment_ratio`.

Поиск использует отсортированные индексы с бинарным поиском, поэтому слияние не замедляется квадратично с длиной записи; `tests/test_merge_equivalence.py` сравнивает индексированный код с простыми эталонными реализациями.

## Выходные файлы подробно

Все пять файлов пишутся из `intermediate/merged.json`; `render` может заново создать их без повторного вывода моделей.

| Файл | Что содержит |
|---|---|
| `transcript.txt` | по строке на реплику: `[чч:мм:сс–чч:мм:сс] Говорящий [пометки]: текст` |
| `transcript.md` | заголовок, короткая заметка о том, что текст автоматический и требует сверки с аудио, затем каждая реплика — жирная строка `[интервал] Говорящий · пометки` и её текст (заголовок и заметка — на русском) |
| `transcript.srt`, `transcript.vtt` | субтитры с настоящими таймингами по границам слов; метка говорящего (и пометки) повторяются в каждом субтитре; строки переносятся по 42 символа; VTT начинается с `WEBVTT` |
| `transcript.json` | слитый JSON, см. ниже; карта говорящих его не меняет, он хранит метки `SPEAKER_nn` |

**Слитый JSON.** Верхний уровень: `schema_version`, `duration_s`, `speakers`, `text`, `raw_text`, `gigastt_processed_text`, `punctuation_alignment_ratio`, `words`, `turns`. У каждого **слова**: `index`, `word`, `display_word`, `start`, `end`, `confidence`, `speaker`, `speaker_overlap_s`, `assignment` (`overlap`, `nearest` или `unknown`), `ambiguous` и `overlap`. У каждой **реплики**: `id`, `speaker`, `start`, `end`, `text`, `raw_text`, `overlap`, `uncertain_words`, `uncertain`, `confidence` (уверенность слов, взвешенная по длительности), `word_start` и `word_end` (индексы в `words`). Значения `speaker` — всегда метки конвейера `SPEAKER_nn`: карта говорящих к этому файлу не применяется.

**Остальные файлы в каталоге задания.** `intermediate/gigastt.json` (проверенный вывод GigaSTT; у каждого слова должны быть `start` и `end`), `intermediate/pyannote.json` (модель, ревизия, запрошенные и найденные говорящие, `speaker_count_matches_request`, regular- и exclusive-сегменты) и `manifest.json` (ниже). Файлы пишутся через временный `.partial` и переименовываются, поэтому прерванная запись не оставляет наполовину записанного результата; если GigaSTT вернул JSON, который программа не может использовать, сырой вывод сохраняется как `gigastt.json.rejected`.

**Манифест.** `manifest.json` содержит `schema_version`, `pipeline_version`, `created_at`, `updated_at`, отпечаток входа `input` (`name`, `size_bytes`, `mtime_ns`, `sha256`; никогда не абсолютный путь), `config` с опциями, влияющими на результат, и словарь `stages` (`audio`, `asr`, `diarization`, `merge`, `render`), в каждом из которых есть `completed_at` и сведения об этапе (например, число слов, найденные метки говорящих, отрендеренные файлы и использованные имена).

## Справочник по конфигурации

`config/default.yaml` читают `run` и `doctor` (`render` его не читает). Неизвестные секции и ключи отвергаются сообщением со списком поддерживаемых ключей. Относительные пути считаются от корня проекта — ближайшего объемлющего каталога с `pyproject.toml`. Опция командной строки, где она есть, переопределяет значение из YAML.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `project.output_root` | `../gigastt-pyannote-output` | куда класть каталоги заданий |
| `audio.diarization_filter` | `null` | фильтр ffmpeg `-af` для копии под диаризацию (по умолчанию его нет) |
| `audio.asr_filter` | `highpass=f=80,loudnorm=I=-18:LRA=11:TP=-2` | фильтр ffmpeg для копии под распознавание |
| `asr.model_variant` | `rnnt` | вариант модели GigaSTT; должен выдавать пословные метки времени |
| `asr.model_dir` | `models/gigastt` | каталог моделей GigaSTT |
| `asr.punctuation`, `asr.itn` | `true` | пунктуация и нормализация чисел (`true`/`false` или `auto`/`on`/`off`) |
| `asr.vad` | `true` | определение речевой активности |
| `diarization.model`, `diarization.revision` | Community-1 и его зафиксированная ревизия | должны совпадать с зафиксированными значениями, иначе запуск отвергается |
| `diarization.model_dir` | `models/pyannote` | каталог кэша Hugging Face для модели |
| `diarization.device` | `cpu` | зафиксированная сборка PyTorch — только CPU |
| `diarization.num_speakers` | `4` | число говорящих, передаваемое pyannote |
| `merge.max_turn_gap` | `1.5` | секунды тишины, разбивающие реплику |
| `merge.nearest_max_gap` | `0.5` | насколько далеко может быть ближайший сегмент, прежде чем слово станет `UNKNOWN` |
| `output.formats` | `json, md, txt, srt, vtt` | записываемые форматы |
| `output.mark_uncertain_words` | `true` | добавлять пометку `спикер под вопросом` |
| `output.subtitle_max_seconds`, `output.subtitle_max_chars` | `6`, `84` | пределы субтитра; `0` отключает предел |

**Что требует `--force`.** Опции, влияющие на результат, — это число говорящих, оба аудиофильтра, вариант модели, пунктуация, ITN, VAD, устройство, два порога пауз, `--allow-downmix` и зафиксированные модель и ревизия. Если манифест существует и любая из них отличается, `run` останавливается с сообщением `Inference/merge options changed; use --force to rebuild.`. Число потоков PyTorch, каталоги и опции `output.*` его не вызывают: опции вывода применяются на этапе рендера, который выполняется при каждом запуске.

**Что переопределяет `run.ps1`.** Обёртка всегда явно передаёт `--output-root`, `--num-speakers` и `--model-dir` (и `--config`). Поэтому через `run.ps1` каталог вывода, число говорящих и каталог моделей GigaSTT берутся из параметров скрипта (`-OutputRoot`, `-NumSpeakers` — по умолчанию 4, и `models\gigastt`), а не из `project.output_root`, `diarization.num_speakers` или `asr.model_dir` в YAML. Чтобы использовать значения из YAML, вызывайте CLI напрямую.

Переменные окружения, которые читает код: `HF_TOKEN` (или `HUGGINGFACE_TOKEN`) для pyannote; `HF_HOME` использует сама библиотека Hugging Face, а `.env.example` направляет его в `models/huggingface`. По умолчанию код также выставляет `PYANNOTE_METRICS_ENABLED=0`, `HF_HUB_DISABLE_TELEMETRY=1` и `DO_NOT_TRACK=1` до импорта pyannote; значение, уже заданное в вашем окружении, сохраняется.

### CLI

Скрипты вызывают его как `uv run --python 3.11 python -m fourvoices.cli <команда>`; `pyproject.toml` также объявляет консольный скрипт `fourvoices`. Коды выхода: `0` — успех, `2` — сообщённая ошибка (`error: …` в stderr, а также неудачный doctor), `130` — прервано Ctrl+C (завершённые этапы можно возобновить).

| Команда | Опции |
|---|---|
| `run` | `--input` (обязательно), `--output-root`, `--config`, `--gigastt-exe`, `--model-dir`, `--num-speakers`, `--speaker-map`, `--speaker-name LABEL=NAME` (повторяется), `--allow-downmix`, `--strict-speakers`, `--force`, `--ffmpeg`, `--ffprobe`, `--model-variant`, `--punctuation auto\|on\|off`, `--itn auto\|on\|off`, `--no-vad`, `--encoder-threads`, `--torch-threads`, `--torch-interop-threads`, `--device`, `--max-turn-gap`, `--nearest-max-gap`, `--formats`, `--output-stem` |
| `render` | `--job-dir` (обязательно), `--speaker-map`, `--speaker-name LABEL=NAME`, `--formats`, `--output-stem`, `--subtitle-max-seconds`, `--subtitle-max-chars`, `--mark-uncertain` / `--no-mark-uncertain` |
| `diarize-preload` | `--model`, `--revision`, `--model-dir` (принимаются только зафиксированные модель и ревизия) |
| `doctor` | `--config`, `--gigastt-exe`, `--model-dir` (принимается, но не используется) |

Замечания по CLI:

- **`render` не читает `config/default.yaml`.** Пределы субтитров и пометки неуверенности по умолчанию берутся из последнего рендера задания (6 с, 84 символа и пометки включены — для заданий, отрендеренных до того, как это стали записывать); `--subtitle-max-seconds`, `--subtitle-max-chars` и `--mark-uncertain` / `--no-mark-uncertain` их переопределяют. Команда отказывается работать, если манифест больше не подтверждает `merged.json`. Без `--formats` он заново рендерит форматы, записанные в манифесте задания.
- **Doctor из CLI проверяет**, что `ffmpeg`, `ffprobe` и исполняемый файл GigaSTT находятся, что установлены `pyannote.audio`, `torch`, `soundfile` и `PyYAML` (он печатает их версии), что токен задан и что конфигурация и зафиксированная модель корректны. Он не проверяет, что файлы моделей существуют, что PyTorch — это CPU-сборка, и хеш исполняемого файла.
- **Прямой вызов CLI.** `run.ps1` ещё и выставляет `GIGASTT_OFFLINE=1`, `GIGASTT_PUNCT_MODEL_DIR` и `GIGASTT_VAD_MODEL_DIR` (в `models\gigastt\punct` и `models\gigastt\vad`) для процесса GigaSTT и загружает `.env` в окружение; при прямом вызове `fourvoices run` задайте те же три переменные сами и убедитесь, что в окне задан `HF_TOKEN` (Python-код читает его только из окружения, но не из `.env`). Пример ниже делает это.
- **Принудительная пересборка:**

```powershell
# Из корня репозитория. Эти переменные живут до закрытия окна PowerShell.
# $env:HF_TOKEN уже должен быть задан (см. раздел «Однократный доступ к gated-модели Hugging Face»).
$gigaModels = (Resolve-Path .\models\gigastt).Path
$env:GIGASTT_OFFLINE = '1'
$env:GIGASTT_PUNCT_MODEL_DIR = Join-Path $gigaModels 'punct'
$env:GIGASTT_VAD_MODEL_DIR = Join-Path $gigaModels 'vad'

uv run --python 3.11 python -m fourvoices.cli run --input .\media\recording.m4a `
    --output-root ..\gigastt-pyannote-output --config config\default.yaml `
```

## Безопасность и воспроизводимость

- Никогда не используйте `git add -f` для аудио, `.env`, `models\` или
  `transcripts\`.
- Перед commit запускайте `.\scripts\check-repo-hygiene.ps1`.
- Рекомендуется задавать `HF_TOKEN` только для текущего процесса PowerShell.
  Локальный `.env` поддерживается как запасной вариант и игнорируется Git.
- Исполняемый файл GigaSTT зафиксирован URL + SHA-256, pyannote — полным git revision. Веса GigaAM RNNT, пунктуации и VAD скачивает сам `gigastt` и сверяет их с SHA-256, вшитыми в закреплённый исполняемый файл; файлы RNNT перепроверяются при каждой загрузке. Веса pyannote закреплены только ревизией.
- Телеметрия выключена: метрики использования pyannote и телеметрию Hugging Face Hub отключает сам код, что бы ни было задано в оболочке.
- Первое скачивание требует сети; сама обработка после подготовки моделей
  выполняется локально.

Автоматическая транскрипция не является дословной гарантией. Для юридически
значимых цитат обязательно сохраняйте оригинал, таймкод и вручную сверяйте
слова на слух.

## Диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `error: Set HF_TOKEN after accepting the Community-1 model conditions on Hugging Face.` | в этом окне PowerShell нет токена (он нужен при каждом запуске, а не только при скачивании) | задайте `$env:HF_TOKEN` заново или положите токен в локальный `.env` |
| `Could not load Community-1. Confirm model access and HF_TOKEN.` или `Model download was denied.` | условия модели не приняты либо токен неверный | примите условия на странице модели и создайте токен **Read** |
| `error: Input has 2 channels (…). Inspect/listen to the channels first …` | многоканальный вход намеренно отвергается | послушайте каналы; `-AllowDownmix` — только если сведение не может разрушить полезное разделение говорящих |
| `Inference/merge options changed; use --force to rebuild.` | опция, влияющая на результат, отличается от записанной в манифесте | верните опцию либо пересоберите с `--force` через CLI (у `run.ps1` нет `-Force`) |
| `Existing job belongs to a different input; use --force.` | в каталоге задания с таким именем лежит другой файл | используйте `--force`, только если вы действительно хотите заменить его |
| `Configuration problems: unknown key '…'` | опечатка или устаревший ключ в YAML | используйте один из ключей, перечисленных в сообщении; см. [Справочник по конфигурации](#справочник-по-конфигурации) |
| `This release is pinned to … the configuration requests an unreviewed artifact.` | изменены `diarization.model` или `revision` | верните зафиксированные значения |
| `ffmpeg is not available on PATH. Install FFmpeg and restart the shell.` | ffmpeg только что поставлен через winget | откройте новое окно PowerShell, вернитесь в каталог репозитория и задайте токен заново |
| `Не найден GigaSTT. Запустите .\scripts\download-models.ps1.` | исполняемый файл ещё не скачан | запустите `.\scripts\download-models.ps1` |
| `SHA-256 GigaSTT не совпал…` | повреждённая или подменённая загрузка | запустите `.\scripts\download-models.ps1 -SkipPyannote -Force` |
| `warning: Requested 4 speakers but pyannote returned N …` | один из участников почти молчал либо говорящих не четверо | результат сохранён; укажите `-NumSpeakers` либо `-StrictSpeakers`, чтобы сделать это ошибкой (результат всё равно сохраняется) |
| `warning: these labels are not in the transcript and were ignored: …` | метки из карты говорящих нет в этом задании | используйте метки из сообщения |
| `GigaSTT JSON has no 'words' array; word timestamps are required.` и файл `gigastt.json.rejected` | GigaSTT вернул то, что программа не может использовать (например, вариант модели без пословных меток времени) | посмотрите файл `.rejected`; используйте вариант, выдающий пословные метки времени |
| `error: Cannot read …/manifest.json …` | повреждённый манифест | исправьте или удалите его; без манифеста этапы пересчитываются, а не используются повторно |
| запуск очень медленный или занимает много памяти | только CPU, а диаризация загружает всю запись в память | см. [Требования](#требования); настройте `-TorchThreads`; обрабатывайте файлы по одному (скрипт так и делает) |

## Статус и известные ограничения

Версия пакета — 0.1.0.

- **Платформа.** Только Windows 10/11 x64: скрипты — PowerShell и используют winget; CI работает на `windows-latest`. Другие платформы не документированы и не тестируются.
- **Язык и говорящие.** Русская речь; значения по умолчанию рассчитаны на четырёх говорящих на одном микрофоне. Число говорящих задаётся, а не определяется.
- **Только CPU.** Зафиксированная сборка PyTorch — `2.11.0+cpu`; пути через GPU нет.
- **Файлы обрабатываются по одному** скриптом `run.ps1` — намеренно.
- **Память.** Диаризация загружает всю запись; примерно 230 МБ на час аудио плюс сама модель (см. [Требования](#требования)).
- **Фиксации неполные.** Исполняемый файл GigaSTT (URL и SHA-256) и ревизия pyannote зафиксированы; веса GigaAM RNNT, пунктуации и VAD скачивает `gigastt`, этот репозиторий сам их не закрепляет (`gigastt` сверяет их с SHA-256, вшитыми в закреплённый исполняемый файл), а веса pyannote закреплены только ревизией. Версии зависимостей зафиксированы в `pyproject.toml` и `uv.lock`.
- **Токен при каждом запуске.** `HF_TOKEN` требуется каждый раз, когда выполняется диаризация, даже если все веса уже на диске.
- **Сеть.** Установка и скачивание моделей требуют сети. После этого обработка локальная; код по умолчанию отключает телеметрию pyannote, но значение, уже заданное в вашем окружении, имеет приоритет.
- **Точность.** Автоматическая транскрипция не гарантирует дословной точности; перекрытия речи и перебивания требуют ручной вычитки.
- **Тесты.** Набор pytest покрывает CLI и возобновление, обработку диаризации, обёртку над GigaSTT, слияние (включая совпадение с эталонными реализациями) и рендер; CI запускает ruff, pytest и проверку гигиены. Тесты используют заглушки вместо моделей, поэтому полный сквозной запуск на реальной записи требует настоящих моделей и токена.
- **Процесс выпуска не описан**; репозиторий используется из рабочей копии.
